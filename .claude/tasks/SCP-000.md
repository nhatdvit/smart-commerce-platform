## Description

Install the Git-driven, agent-based development workflow this directory is part
of: specialised agents, the eight workflow skills, the task ledger, review
report templates, safety hooks, workflow documentation and a traceability CI
gate.

Id `SCP-000` rather than `SCP-001` on purpose: this is the scaffolding the
numbered work runs through, not a product feature. It is also recorded here
because a workflow that exempts its own installation from its own ledger is
making a claim it does not believe.

It was installed directly rather than through `/task` → `/plan` → `/implement`,
for the obvious reason that none of those existed yet. The design was approved
as a Phase A proposal before any file was written, which is the same gate
`/plan` enforces.

## Technical Plan

Presented and approved as the Phase A proposal. In short:

- Orchestration lives in **skills**, which run in the main session, because a
  subagent cannot delegate to another subagent. An agent definition that told
  one agent to call another would simply not work, and the brief forbids
  inventing unsupported orchestration.
- Enforcement is split three ways by what each mechanism can actually do:
  skills validate state, hooks hard-block irreversible operations with
  `exit 2`, and CI gates the pull request. Merge approval belongs to GitHub and
  cannot be enforced from here.
- `settings.json` carries hooks only, no `permissions` block. Tool permissions
  are the operator's security setting, and the brief warns specifically against
  shipping permissive ones.
- The existing `ci.yml` is left alone. Its seven jobs already cover the brief's
  quality gates; adding to them would duplicate work and slow every run.

### Fix round 1 — 2026-11-12

| Finding | Decision | What changed |
| --- | --- | --- |
| **F1** (HIGH, AC8) | confirmed in part | Root cause was environmental: the session that produced commit `58869f9` was started in `D:project_newsmart-commerce-platform`, a checkout with no `.claude/` directory, so no hook was ever registered. Proven by running a command matching a block rule in that session and watching it succeed. The script itself was correct. But the audit found a real latent defect next to it, and that is fixed: both hooks carried an `if: "Bash(git commit *)"` pre-filter, and the idiom this repository actually uses — `git add -A && git commit ...` — does not *start* with `git commit`, so a prefix match could skip both the ledger and the secret scan on the commonest commit shape. The pre-filters are gone; each hook now filters on `/gits+commit/` inside the script, which matches a compound command. Cost: one Node start per shell call. |
| **F2** (MEDIUM, AC4) | confirmed | Seven rule patterns widened and three rules added in `guard-protected-ops.mjs`. The guards previously matched only the canonical spelling of each operation and allowed the shapes people mistype: `git push -fu`, `--mirror`, `+main`, `origin :main`, `push -d`, `commit -n`/`-nm`, `echo x>.env`, `tee -a .env`, `docker-compose down -v`, `down -fv`, `migrate --env=production`. New rules: `write-dotenv-indirect` (`cp`/`mv`/`install`/`sed -i` onto `.env`), `bypass-hooks-path` (`-c core.hooksPath=`), `auto-merge-pr-api` (`gh api .../pulls/N/merge`). `selftest.mjs` gained 17 block fixtures and 6 allow fixtures; it reports **82 passed, 0 failed**, up from 60. The allow fixtures matter as much: `commit -am`, `push --dry-run`, `cp .env.example .env.backup`, `echo APP_KEY= > .env.example`, `docker compose down` must stay allowed, because a guard people route around has no value. |

The four agents now return the report in the template's shape as their final message, and the calling skill transcribes it. Reading what you are about to save is already step 4 of `/test`. |
