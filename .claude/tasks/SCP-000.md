## Description

Install the Git-driven, agent-based development workflow this directory is part
of: specialised agents, the eight workflow skills, the task ledger, review
report templates, safety hooks, workflow documentation and a traceability CI
gate.

Id `SCP-000` rather than `SCP-001` on purpose: this is the scaffolding the
numbered work runs through, not a product feature. It is also recorded here
because a workflow that exempts its own installation from its own ledger is
making a claim it does not believe.

It was installed directly rather than through `/task` → `/plan` → `/implement`,
for the obvious reason that none of those existed yet. The design was approved
as a Phase A proposal before any file was written, which is the same gate
`/plan` enforces.

## Technical Plan

Presented and approved as the Phase A proposal. In short:

- Orchestration lives in **skills**, which run in the main session, because a
  subagent cannot delegate to another subagent. An agent definition that told
  one agent to call another would simply not work, and the brief forbids
  inventing unsupported orchestration.
- Enforcement is split three ways by what each mechanism can actually do:
  skills validate state, hooks hard-block irreversible operations with
  `exit 2`, and CI gates the pull request. Merge approval belongs to GitHub and
  cannot be enforced from here.
- `settings.json` carries hooks only, no `permissions` block. Tool permissions
  are the operator's security setting, and the brief warns specifically against
  shipping permissive ones.
- The existing `ci.yml` is left alone. Its seven jobs already cover the brief's
  quality gates; adding to them would duplicate work and slow every run.

### Fix round 3 — 2026-11-16

Closes **S4/M6**, the one blocking finding fix round 2 left open. The Tech Lead
was asked whether to accept the documentation fix and open a separate task for
the structural one, or to drop `Bash` now. They chose to drop it.

`code-reviewer`, `security-reviewer` and `performance-reviewer` now hold
`Read`, `Glob`, `Grep` and nothing else. There is no channel through which
they can write a file, so "a reviewer cannot fix what it finds or author its
own verdict" is a property of the tool grant rather than a sentence in a
prompt. That is what S4 asked for.

`qa-engineer` and `git-release` keep `Bash`, deliberately and on the
record: the first has to execute the suites, the second has to run git. Their
independence still rests on the agent, and both `docs/workflow/README.md` and
`quality-gates.md` now say so in the same row as the claim, instead of
lumping all five under one "**no**".

**What this cost, stated rather than glossed.** The three reviewers used
`Bash` to read the diff, to run `pnpm audit` and `composer audit`, to take
a query plan with `EXPLAIN ANALYZE`, and to execute the code under review. It
is worth being precise about how much that mattered: both reports on this very
task were built that way. The security reviewer imported `scanDiff` and
`evaluate` and drove them; the code reviewer ran the guards over ~55 crafted
commands and ran the gate against this branch. Reading alone would not have
produced those findings with that confidence.

What replaces it:

- `/review` writes the diff to `.claude/reviews/<ID>/diff.patch`, which is
  gitignored, and gives each agent the path. They read it.
- An agent that needs a command run asks for it in its report, naming the
  command and what it expects to learn. The calling session runs it and sends
  the output back with `SendMessage`, and the agent revises.
- The report must say who ran what.

**The trade, named so nobody has to rediscover it:** weaker independence of
*evidence*, stronger independence of *action*. The session running those probes
is usually the session that wrote or fixed the code, which is an interested
party — that is a real loss and it is not hidden. Against it, an agent with no
write channel cannot author a clean verdict for work it did itself, and that is
the failure that empties a review of meaning rather than merely weakening it.

Files changed: the three agent definitions (frontmatter and the body sections
that told them to run `git`), `.claude/skills/review/SKILL.md` (step 2 now
materialises the diff and documents the ask-for-a-command protocol, step 4
states the boundary), `docs/workflow/README.md` (the agent table gains a Tools

### Fix round 4 — 2026-11-17

The four HIGH findings from the second pass are closed, each with a measurement
rather than an argument. `pnpm claude:selftest` went from 60 to 139 assertions,
and every one of these has a regression test.

**S15/H1 — the guard refused 24 of this repository's own files.** The reviewer's
suggested remedy was to make all content rules advisory. That was not taken,
because it would also have stopped blocking `MAIL_PASSWORD=<a real value>`,
which fix round 2 had just closed as S2 — trading one HIGH for another.

What was done instead grades the rules by how certain they are. Forbidden paths
and unmistakable token shapes stay blocking. The generic `key = value` rule is
now graded by the **shape of the value**: an expression, a version, a bare word,
or anything containing code, shell, template or regex markers is never blocked,
while a mixed-class literal still is. Every one of the 33 false findings failed
on the value, not the key — `$value`, `{item.id}`, `3.1.1`, `generate` — which
is why this works where tightening the key list did not.

Three smaller corrections came out of actually measuring it:

- `.npmrc` was a forbidden *path*, and this repository tracks one containing
  pnpm resolution settings and no credentials, so every commit touching it was
  blocked. The path rule is gone, replaced by an `_authToken=` content rule
  that catches the dangerous thing in any file instead of one filename.
- `hunter2` and two other well-known joke credentials are now placeholders. The
  first appears in this project's own redaction test, where containing a fake
  password is the point of the file.
- Values holding `${`, `{{`, `::`, `->`, `=>`, brackets, `|`, `*` or `\` are
  rejected as literals. `/` and `+` are deliberately **not** in that list,
  because base64 uses both.
